Estado (2 de noviembre de 2026): en desarrollo. La SF se distribuye como el plugin sf, cuya versión publicada es la del último tag vX.Y.Z (y la version de plugin.json en main); JKanban tiene MCP, pero aún no está instalado en la SF; varias propuestas esperan aprobación.

Una fábrica de software personal sobre Claude Code. Reúne el método y las herramientas con los que una sola persona, el «hombre orquesta», lleva a término muchos proyectos a la vez. Esa persona cada día desarrolla, investiga, crea proyectos y visiones, enseña, aprende y se mantiene al día.

La SF no parte de cero: integra todo lo que ya existe y sirve, entero o en parte. Claude Code es su sistema nervioso central. Su objetivo no es producir más, sino pedir menos atención.

Los documentos distinguen acuerdos, propuestas y pendientes.

Instalar

Requisitos: Claude Code, git, gh con la sesión iniciada (gh auth login) y Python 3.9 o posterior. Funciona en Windows, macOS y Linux.

Una sola vez por equipo:

claude plugin marketplace add jumibot/SoftwareFactory
claude plugin install sf@softwarefactory --scope user

Después, reinicia Claude Code. Instalar sf trae solas sus tres dependencias (gsap-skills, threejs-skills y oklch-skill). Más detalle, en el README del plugin.

La SF tiene licencia MIT (LICENSE); lo que toma de terceros y sus licencias, en plugins/sf/LICENCIAS-DE-TERCEROS.md.

Skills

Todas las skills de la SF viven dentro del plugin sf, en plugins/sf/skills/. Su procedencia (qué se tomó, de dónde y qué se cambió) está en docs/referencias/procedencia/; la atribución y las licencias de lo que es de terceros, en plugins/sf/LICENCIAS-DE-TERCEROS.md. El plugin se publica en GitHub y se instala para el usuario, así que las skills están en cualquier proyecto con el prefijo sf: (por ejemplo, sf:documento_vision). Ver plugins/sf/README.md.

Propias

Skill Para qué Estado
crear_documentos Lo común para crear cualquier documento: generador .md → HTML, catálogo de recursos, temas e identidad, herramientas de lectura, respaldo y comprobación Nueva
documento_vision Documentos de visión, en conversación de cuatro fases, con HTML de estilo propio Validada
documento_fundacional Documento fundacional: presentación formal del proyecto, sin historia, con evidencias, escenarios y fuentes; HTML editorial imprimible Nueva, sin validar
informe_deliberativa Informe de una tarea deliberativa: estructura fija, preguntas con opciones, recomendación y estado, y una versión con respaldo y HTML en cada vuelta Nueva
infografia_tecnica Infografías técnicas en 3D e interactivas de un producto o dispositivo Validada
diseno_interfaz Interfaz en detalle antes de la técnica: recorridos, pantallas, estados y criterios Sin probar
definicion_tecnica Definición técnica y arquitectura, con decisiones en formato MADR Sin probar

Externas, de apoyo. No viajan en el plugin: son dependencias de sf y se instalan con él (decisiones 175 y 176). Se invocan con el prefijo de su plugin.

  • oklch-skill: color en OKLCH, paletas y contraste. Viene de jakubkrehel/oklch-skill, fijada al commit 0e81f04. La usa crear_documentos para crear las series de colores de los temas; se invoca como oklch-skill:oklch-skill.

  • gsap-skills: animación web, de las skills oficiales de GreenSock (greensock/gsap-skills), fijada al commit aed9cfd. La usa infografia_tecnica con cinco de sus skills: core, timeline, plugins, utils y performance.

  • threejs-skills: 3D en la web, de CloudAI-X/threejs-skills, fijada al commit 0e18186. La usa infografia_tecnica con diez de sus skills: fundamentals, geometry, materials, lighting, textures, animation, interaction, shaders, postprocessing y performance.

crear_documentos necesita además dataviz para validar las series de colores; no es un plugin y la trae el entorno. Si no está, la skill dice qué hacer.

Cómo se trabaja
  • Generar el HTML de una visión o de un informe:
python -I -X utf8 plugins/sf/skills/documento_vision/scripts/doc_to_html.py docs/specs/vision/hombre-orquesta.md
python -I -X utf8 plugins/sf/skills/documento_vision/scripts/doc_to_html.py "docs/referencias/reports/<informe>.md" --tipo "Informe de investigación"

El script encuentra solo la identidad de docs/identidad/. El .html no se edita a mano.

  • Regenerar README.html cada vez que cambie el README:
python -I -X utf8 scripts/readme_a_html.py

  • Cambios en la SF: cada tarea, en su rama feature/NN-nombre desde develop; probada, entra en develop por squash y push. Publicar es pasar develop a main con el tag vX.Y.Z (metodología, 2).

  • Mejoras: se registran en propuestas con su origen, aunque surjan en otro proyecto, y se aplican solo con aprobación del propietario. Al decidirse, pasan a decisiones.

  • Información que falta: se pide; no se inventan requisitos ni decisiones.
