# Botón ACTUALIZAR: el plugin sf, solo cuando hay versión publicada nueva

- **Origen:** SoftwareFactory, 2026-10-29, tarea 161. El propietario: «añadir un botón de ACTUALIZAR»; actualiza «el plugin, solo cuando haya versión nueva».
- **Contexto:** al publicar con RELEASE, el plugin instalado no se pone al día solo: había que lanzar `claude plugin update sf@softwarefactory` en cada scope (el de usuario y el local de cada proyecto) y reiniciar.
- **Decisión:** la primera fila de la cabecera lleva un botón ACTUALIZAR, junto a RELEASE, que solo sale cuando la última versión publicada (el tag `vX.Y.Z` más alto del repositorio del catálogo) es mayor que la instalada de `sf@softwarefactory` en algún scope que use el proyecto. Muestra la versión nueva y pide confirmarla con un segundo clic, como RELEASE. Al confirmar, con comandos y sin Claude, refresca siempre antes el catálogo (`claude plugin marketplace update softwarefactory`), porque el botón ve la versión en GitHub y `claude plugin update` la busca en el clon local, que solo se refresca al arrancar y si la actualización automática está activada; después actualiza el plugin en cada uno de esos scopes y avisa de que hay que reiniciar Claude Code. Si el refresco falla, no actualiza y lo dice. Si Claude Code responde que ya tenía esa versión («already at the latest version»), se anota igualmente en `installed_plugins.json` como actualizada y no se pide reiniciar. El botón va en rojo, para no confundirlo con el violeta de RELEASE.
- **Consecuencias:** publicar y actualizar quedan en dos botones; los proyectos consumidores ven cuándo hay versión nueva sin tener que preguntar.
- **Aplicada en:** plugins/sf/hooks/panel.tsx, plugins/sf/hooks/cola.ts, plugins/sf/hooks/register.tsx, plugins/sf/hooks/lectura.ts, plugins/sf/types/index.d.ts y plugins/sf/tests/panel.test.tsx.
