# Todas las skills externas actuales, como dependencias

- **Origen:** SoftwareFactory, 2026-11-01, tarea «Inventario de las skills externas que usa la SF» (255). Tras saber que las 16 copias del plugin son idénticas a sus originales, el propietario: «quiero que todas las skills externas vayan como dependencia».
- **Contexto:** la decisión 175 manda que una skill externa usada tal cual sea una dependencia. Un plugin de Claude Code declara dependencias con `dependencies` en su `plugin.json`, pero solo de otros plugins. `gsap-*` vienen de un repositorio que ya es plugin (`greensock/gsap-skills`); `threejs-*` (`CloudAI-X/threejs-skills`) y `oklch-skill` (`jakubkrehel/oklch-skill`), no. El marketplace de la SF puede apuntar a un repositorio ajeno, fijado a un commit, y elegir qué skills carga.
- **Decisión:** las 16 skills externas que hoy viajan en el plugin (`gsap-*`, `threejs-*` y `oklch-skill`) dejan de copiarse y pasan a ser dependencias de `sf`, que se instalan al instalar el plugin. Ninguna se quita. Las tres (`gsap-*`, `threejs-*` y `oklch-skill`) se toman de una entrada en el marketplace de la SF fijada a su commit, para que instalar `sf` las traiga sin añadir antes ningún catálogo ajeno (el propietario: «ok a la medida 1»). Al principio se eligió el marketplace oficial de GreenSock para `gsap-*`, sin fijar versión; se descartó porque, sin ese catálogo añadido antes, `sf` no carga. `dataviz` queda como requisito del entorno, anotado en `documento_vision` con qué hacer si no está.
- **Consecuencias:** se invocarán con el prefijo de su plugin, no con `sf:`, y las skills propias que las nombran se ajustan. Hay que probar la instalación antes de publicar. Las versiones de las dependencias las mueve la SF, cambiando el commit, cuando le interesa. Como `claude plugin update` no instala las dependencias nuevas y, si falta una, `sf` no carga (ni su panel), el botón ACTUALIZAR del panel, mientras aún corre la versión vieja, instala las dependencias que falten de la versión nueva antes de recargar; la nota de cada versión lleva la orden para quien actualice a mano. Antes de publicar se prueban, en una configuración desechable, la instalación desde GitHub y ACTUALIZAR con una dependencia nueva (el propietario: «ok a la medida 2»).
- **Aplicada en:** `marketplace.json` (entradas `gsap-skills`, `threejs-skills` y `oklch-skill`, fijadas a su commit), `dependencies` del `plugin.json` de `sf`, copias retiradas de `plugins/sf/skills/`, `infografia_tecnica` y `documento_vision` (prefijos y procedencia; `dataviz` como requisito del entorno), especificación, 2, README y `plugins/sf/README.md`.
