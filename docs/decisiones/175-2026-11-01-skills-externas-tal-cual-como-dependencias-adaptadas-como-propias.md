# Skills externas: tal cual, como dependencias; adaptadas, como propias

- **Origen:** SoftwareFactory, 2026-11-01, tarea «Inventario de las skills externas que usa la SF» (255). El inventario encontró 16 skills de terceros copiadas enteras en el plugin, 15 sin origen ni versión registrados, y una contradicción entre la especificación (se copian enteras) y la propuesta P07 (se estudian y se reescriben). El propietario: «todas las skills externas que se usen tal cual deben ser dependencias y resolverse al instalar el plugin... En caso de personalizaciones ya serían "versiones nuestras" que distribuiríamos con el plugin pero solo en ese caso».
- **Contexto:** la decisión 007 llevó al plugin copias enteras de las skills externas. Así no se actualizan, no consta de dónde vienen y pesan en el contexto aunque no se usen.
- **Decisión:** una skill externa que la SF usa tal cual no se copia en el plugin: se declara como dependencia y se resuelve al instalar el plugin. Solo viaja en el plugin una skill externa personalizada; entonces es una versión nuestra, con su origen y lo que cambia anotados.
- **Consecuencias:** sustituye lo que la decisión 007 y la sección 2 de la especificación dicen sobre copiar enteras las skills externas. Hay que comprobar cómo declara dependencias un plugin de Claude Code y qué hacer con las copias actuales (`gsap-*`, `threejs-*`, `oklch-skill`) y con `dataviz`, de la que depende `documento_vision`. La P07 queda superada en lo que choca con esta regla.
- **Aplicada en:** especificación, 2 (acuerdo del 2026-11-01); README; P07 y P18; nota en la decisión 007. Al plugin, en la 176.
