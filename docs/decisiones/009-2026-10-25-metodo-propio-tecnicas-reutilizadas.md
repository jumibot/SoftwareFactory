# Método propio, técnicas reutilizadas

- **Origen:** SoftwareFactory, 2026-10-25, revisión de la visión: «propongo cambios de metodología que se adaptan a mi forma de trabajo y mis proyectos, pero las técnicas no las quiero definir sino reutilizar». Aprobada con «Ok a todo».
- **Contexto:** Spec Kit, Superpowers y BMAD ya resuelven técnicas que la SF solo tenía planificadas.
- **Opciones:** escribir técnica propia; montar el método como *preset* de Spec Kit (descartado: arrastra su programa, una rama por funcionalidad y un orden fijo sin aprobación humana); capas finas sobre técnicas ajenas.
- **Decisión:** la SF define el método y reutiliza las técnicas. Cada skill de paso es una capa fina sobre técnicas ajenas adaptadas. Brain, KB, agente, API e interfaz web son opcionales según el proyecto.
- **Consecuencias:** skills `diseno_interfaz` y `definicion_tecnica`, sin validar todavía en LecturaFàcil.
- **Aplicada en:** metodología (principios, 3.2, 3.3, 6 y 8); especificación, 2; visión.
